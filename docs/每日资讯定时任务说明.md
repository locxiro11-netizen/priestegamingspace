# 每日资讯定时任务 · 运维说明

> 最后更新：2026-09-01

## ⚠️ 重要结论：GitHub 自带调度器对本仓库无效

2026-09-01 实测确认：本仓库的 `schedule` 事件**从未被派发过**，历史累计 0 条。
不是延迟、不是整点拥堵 —— 是调度器对本仓库根本不触发。

验证过程：

1. 三档错峰 cron（UTC 01:07 / 01:47 / 02:37）在 2026-09-01 全部静默跳过，一次都没跑。
2. 对 workflow 执行 disable → enable 强制重新注册（API 确认 `updated_at` 已刷新为当天）。
3. 再加一条临时探针 cron `0 3 * * *`，等到 UTC 03:07 —— 依然 0 条。

同期对照：手动触发（`workflow_dispatch`）、外部触发（`repository_dispatch`）、
push 触发全部正常。说明 Actions 本身没问题，只有 schedule 调度器不工作。

**因此每日发布必须依靠外部定时服务**，见下方配置。

## 触发方式一览

| 触发方式 | 时间（北京时间） | 当前状态 | 说明 |
|---|---|---|---|
| **外部触发**（cron-job.org） | 09:05 | ✅ **实际生效** | 主力通道，见下方配置 |
| 定时 主档 / 备档一 / 备档二 | 09:07 / 09:47 / 10:37 | ⚠️ 未生效 | cron 保留，万一调度器恢复可自动接管 |
| 手动 | 随时 | ✅ 可用 | Actions 页面点 Run workflow，强制执行 |

去重护栏：workflow 第二步会读近 50 条提交，若已存在
`📰 自动发布游戏资讯 N 条 - 今天日期`，则当天不再重复发布。

- `workflow_dispatch`（页面手动点）→ **不受护栏约束**，强制重跑
- `schedule` / `repository_dispatch`（定时与外部触发）→ **受护栏约束**，一天只发一次

## 配置外部触发（必做）

用 cron-job.org（免费、无需信用卡）定时调 GitHub API，绕开 GitHub 自身的调度器。

1. 注册 https://cron-job.org 并登录
2. 右上角 **Create cronjob**
3. **Common** 页签：
   - Title：`PriesteGamingSpace 每日资讯`
   - URL：`https://api.github.com/repos/locxiro11-netizen/priestegamingspace/dispatches`
4. 切到 **Advanced** 页签：
   - Request method：`POST`
   - Custom headers：添加两行
     - `Authorization` = `Bearer 你的令牌`
     - `Content-Type` = `application/json`
   - Request body：`{"event_type":"daily-news"}`
5. **Schedule** 页签：
   - 选 `Every day`，时间填 `01:05`（这是 UTC，等于北京时间 09:05）
   - Time zone 选 `UTC`
6. 保存后点 **Test Run**，返回 `204 No Content` 即配置成功

> cron-job.org 的免费额度是每分钟检测一次，一天一次绰绰有余。
> 它会在任务连续失败时发邮件提醒你，比 GitHub 静默跳过强得多。

## 所需令牌

外部触发需要一个能写该仓库的 GitHub 令牌：

- 经典令牌：https://github.com/settings/tokens/new?scopes=repo,workflow
  （勾 `repo` + `workflow`，最简单）
- 细粒度令牌：https://github.com/settings/personal-access-tokens/new
  （Repository access 选本仓库，权限给 `Contents: Read and write`、`Actions: Read and write`、
  `Workflows: Read and write`）

建议单独建一个只用于触发的令牌，方便随时吊销，不影响其他用途。

## 保活心跳

`keepalive.yml` 每月 1 日 11:23（北京时间）推一次时间戳提交，
用于规避「仓库连续 60 天无活动 → GitHub 禁用 scheduled workflow」。

注意：它本身也是 schedule 触发，目前同样不会跑。
但只要每日资讯正常发布，仓库每天都有提交，60 天无活动的风险就不存在，
所以这条目前不影响使用。若日后长时间停发，再手动处理即可。

## 需要的仓库 Secrets

在 Settings → Secrets and variables → Actions 配置：

- `GH_PAT` —— 必需。用于推送提交（内置 GITHUB_TOKEN 的提交不会触发部署工作流）。
  需要 `repo` 权限；细粒度 token 需给 Contents: Read and write。
- `LLM_API_KEY` —— 必需。当前默认走 Zhipu GLM（glm-4-flash）。
- `LLM_ENDPOINT` / `LLM_MODEL` —— 可选，留空则用默认值。

> 注意：`GH_PAT` 是**发布资讯用的**，与外部触发用的令牌可以是两个不同的令牌，
> 也可以复用同一个。撤销其中一个时要分清楚。

## 排查手册

**今天没生成，怎么查？**

1. 看 Actions 页面「每日游戏资讯自动发布」的运行记录，先看**有没有运行**。
   - 完全没有运行 → 触发通道没工作（外部 cron 挂了 / 还没配）。
   - 有运行但已跳过 → 护栏判定当天已发布，属正常。
2. 用 `?query=event%3Aschedule` 过滤 —— 本仓库此项长期为 0，属已知情况，不是新问题。
3. 若跑了但没发布，看「大模型精选」这步的日志 ——
   `publish.py` 在「今天没爆点」时按 exit 0 正常退出，不算失败。
4. 外部触发是否成功，去 cron-job.org 的任务历史里看 HTTP 状态码，204 即成功。

**手动补发今天的资讯**：Actions → 每日游戏资讯自动发布 → Run workflow → Run workflow。
手动触发不受护栏约束，一定会跑；重复条目由 `source_url` 去重拦截，不会发重。
