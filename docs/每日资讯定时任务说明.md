# 每日资讯定时任务 · 运维说明

## 触发方式一览

| 触发方式 | 时间（北京时间） | 说明 |
|---|---|---|
| 定时 主档 | 09:07 | 错峰，避开 GitHub 整点拥堵 |
| 定时 备档一 | 09:47 | 主档被平台丢弃时兜底 |
| 定时 备档二 | 10:37 | 再兜一层 |
| 手动 | 随时 | Actions 页面点 Run workflow |
| 外部触发 | 自定义 | 见下方 repository_dispatch 配置 |

三档定时不会重复发布：workflow 第二步「护栏」会读取近 50 条提交，
若已存在 `📰 自动发布游戏资讯 N 条 - 今天日期`，后续档位自动跳过。
手动 / 外部触发不受护栏限制，强制执行。

## 为什么原来没跑起来

原配置是 `cron: '0 1 * * *'`（整点）。GitHub 官方明确说明：
scheduled workflow 在平台高负载时段会被延迟，甚至**直接丢弃**。
整点是全球所有仓库最拥挤的时刻，免费仓库尤其容易被丢。
加上定时任务是当天才推上 main、cron 注册有延迟，首个周期被跳过，
最终结果是 `event:schedule` 的运行记录为 0 条。

## 配置外部触发（最稳的一层，可选）

用 cron-job.org 等免费服务定时调 GitHub API，绕开 GitHub 自身的 schedule 调度。

- URL：`https://api.github.com/repos/locxiro11-netizen/priestegamingspace/dispatches`
- Method：`POST`
- Headers：
  - `Accept: application/vnd.github+json`
  - `Authorization: Bearer <你的 GH_PAT>`
  - `Content-Type: application/json`
- Body：`{"event_type":"daily-news"}`
- 建议时间：北京时间 09:05

配好后可先手动点一次 Test run，返回 `204 No Content` 即成功。

## 保活心跳

`keepalive.yml` 每月 1 日 11:23（北京时间）推一次时间戳提交。
用途：GitHub 会在仓库连续 **60 天无活动**后自动禁用所有 scheduled workflow，
心跳把活动续上，避免每日资讯任务被静默停掉。

## 需要的仓库 Secrets

在 Settings → Secrets and variables → Actions 配置：

- `GH_PAT` —— 必需。用于推送提交（内置 GITHUB_TOKEN 的提交不会触发部署工作流）。
  需要 `repo` 权限；细粒度 token 需给 Contents: Read and write。
- `LLM_API_KEY` —— 必需。当前默认走 Zhipu GLM（glm-4-flash）。
- `LLM_ENDPOINT` / `LLM_MODEL` —— 可选，留空则用默认值。

## 排查手册

**今天没生成，怎么查？**

1. 看 Actions 页面「每日游戏资讯自动发布」的运行记录。
2. 用 `?query=event%3Aschedule` 过滤，确认定时到底有没有触发。
   若为 0 条 → 是调度问题，不是代码问题。
3. 若跑了但没发布，看「大模型精选」这步的日志 ——
   `publish.py` 在「今天没爆点」时按 exit 0 正常退出，不算失败。
4. 检查是否收到 GitHub 关于 scheduled workflow 被禁用的邮件。

**手动补发今天的资讯**：Actions → 每日游戏资讯自动发布 → Run workflow。
